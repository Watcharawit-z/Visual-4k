# Visual-4k

ทำให้จอ 2560×1440 แสดงผลด้วยรายละเอียดที่ **มาจาก 4K จริง** โดยสร้างจอ 4K เสมือน
ให้ Windows เรนเดอร์เดสก์ท็อปทั้งใบที่ 3840×2160 แล้ว resolve ลงมาที่พาเนลจริง
ด้วยฟิลเตอร์คุณภาพสูงบน GPU

---

## อ่านตรงนี้ก่อน: อะไรทำได้ อะไรทำไม่ได้

จอ 2560×1440 มีพิกเซลจริง 3.68 ล้านจุด **ไม่มีไดรเวอร์หรือซอฟต์แวร์ใดเพิ่มพิกเซล
ฟิสิกส์ได้** ฉะนั้นถ้าความหมายของ "4K" คือจำนวนจุดที่จอเปล่งออกมา คำตอบคือทำไม่ได้
และใครก็ตามที่บอกว่าทำได้ กำลังขายอย่างอื่นให้คุณ

แต่คำถามที่ควรถามจริง ๆ ไม่ใช่ "จอมีกี่พิกเซล" — มันคือ **"แต่ละพิกเซลมีค่าที่ถูกต้อง
แค่ไหน"** และตรงนี้แหละที่ยังมีที่ให้ปรับปรุงอีกเยอะมาก

จอ 1440p ทุกวันนี้เรนเดอร์แบบ 1 ตัวอย่างต่อพิกเซล — GPU ยิงเรย์เดียวกลางพิกเซล
แล้วเอาค่านั้นมาใช้ทั้งพิกเซล เส้นบาง ๆ ที่พาดผ่านครึ่งพิกเซลจึงกลายเป็น "ติด" หรือ
"ไม่ติด" แบบสุ่ม นี่คือ aliasing และเป็นสาเหตุที่ขอบภาพเป็นขั้นบันได ตัวหนังสือขาแหว่ง
และภาพ "ซ่า" เวลาเลื่อนหน้าจอ

Visual-4k เรนเดอร์ที่ 3840×2160 (2.25 ตัวอย่างต่อพิกเซลพาเนล) แล้วรวมค่าลงมา
พิกเซลบนจอคุณจึงได้ค่าที่ **ใกล้เคียงค่าที่ถูกต้องทางฟิสิกส์มากขึ้นจริง** รายละเอียดที่
ได้มา มาจากเรขาคณิตที่ถูก rasterize ที่ 4K จริง ไม่ใช่การเดาจากภาพ 2K

**สรุปสั้น ๆ:** เพิ่มพิกเซลไม่ได้ แต่ทำให้พิกเซลที่มีอยู่ "ถูกต้อง" ขึ้นมากได้ และนั่นคือ
สิ่งที่ตาคนมองว่า "คมเหมือน 4K"

## ผลการวัดจริง

`reference/bench_supersample.py` เรนเดอร์ scene เชิงวิเคราะห์ (zone plate, เส้นบาง
แบบตัวหนังสือ, checkerboard ที่ลู่เข้าหากัน) ที่ 6×6 ตัวอย่างต่อพิกเซลเพื่อใช้เป็น
ground truth แล้วเทียบว่าแต่ละวิธีเข้าใกล้ความจริงแค่ไหน:

| การเรนเดอร์ | PSNR | SSIM | พลังงาน aliasing |
|---|---:|---:|---:|
| 1440p ปกติ (1 ตัวอย่าง/พิกเซล) | 20.32 dB | 0.9609 | 5505 |
| Visual-4k @ 3840×2160 (1.5×) | **25.31 dB** | **0.9865** | **1470** |
| Visual-4k @ 5120×2880 (2.0×) | **30.00 dB** | **0.9949** | **459** |

- ที่ 4K: PSNR **+5.0 dB**, aliasing **น้อยลง 3.7 เท่า**
- ที่ 5K: PSNR **+9.7 dB**, aliasing **น้อยลง 12 เท่า**

รันเองได้: `python3 reference/bench_supersample.py`

### ข้อค้นพบที่ทำให้เปลี่ยนค่า default

สัญชาตญาณบอกว่าให้ใช้ Lanczos-3 แต่ผลวัดบอกตรงกันข้าม — **ที่อัตราส่วน 1.25×–2.0×
ซึ่งเป็นช่วงที่คอมโพสิเตอร์นี้ทำงานจริง Lanczos-3 แพ้ Lanczos-2 ทุกกรณี** เพราะ sinc
ที่กว้างกว่าจะคุ้มก็ต่อเมื่อมี stopband ให้กดเยอะ ๆ ซึ่งที่ 1.5× ไม่มี lobe ที่เกินมา
เลยเหลือแต่ ringing ค่า default จึงเป็น `lanczos2`

## สิ่งที่โปรเจกต์นี้ **ไม่** ทำ

- **ไม่ได้อัปสเกลภาพ 2K ให้เป็น 4K** การขยายภาพไม่สร้างข้อมูลใหม่ มีเทสต์ยืนยันไว้ที่
  `test_upscaling_cannot_invent_detail` — ภาพที่อัปสเกลแล้วยังคง "นุ่ม" กว่าของจริง
  วัดได้ (ประมาณ 0.6× ของความคมจริง)
- **ไม่ได้ทำให้เกมเร็วขึ้น** ตรงกันข้าม: เรนเดอร์ที่ 4K ใช้พิกเซลมากขึ้น 2.25 เท่า
  นี่คือการแลกเฟรมเรตกับคุณภาพ ไม่ใช่ของฟรี
- **ไม่ใช่ neural upscaler** ทุกอย่างในนี้เป็นฟิลเตอร์เชิงพื้นที่ที่รันได้ในงบ latency
  ของ 1 เฟรม

### ถ้าคุณใช้การ์ด NVIDIA หรือ AMD อยู่แล้ว ลองอันนี้ก่อน

NVIDIA **DSR** และ AMD **VSR** ทำแนวคิดเดียวกันนี้ในไดรเวอร์ ถ้าเปิดใช้ได้และพอใจ
กับผล คุณไม่จำเป็นต้องติดตั้งอะไรจากที่นี่เลย — เปิดใน NVIDIA Control Panel →
Manage 3D Settings → DSR - Factors ข้อได้เปรียบของ Visual-4k คือครอบคลุมเดสก์ท็อป
ทั้งใบ (DSR ใช้ได้เฉพาะกับเกม/แอปที่เรนเดอร์เอง), เลือกฟิลเตอร์ได้เอง, และทำงาน
เหมือนกันทุกยี่ห้อการ์ดจอ

## สถาปัตยกรรม

```
   Visual4kDisplay (IddCx driver)      จอ 4K เสมือน — Windows จัดเดสก์ท็อปที่ 3840×2160
              │                        ไดรเวอร์ไม่แตะพิกเซลเลย หน้าที่คือ "มีตัวตน" อย่างเดียว
              ▼
   DXGI Desktop Duplication            ดึงเฟรมที่ประกอบเสร็จแล้ว (หน้าต่าง + เคอร์เซอร์ + DWM)
              │
              ▼
   visual4k-host (D3D11 compute)       resolve แนวนอน → แนวตั้ง → RCAS sharpen
              │
              ▼
   พาเนลจริง 2560×1440
```

เหตุผลที่ไดรเวอร์ไม่ประมวลผลพิกเซลเอง: IddCx swap-chain processor ไม่มีทางที่ถูกต้อง
ในการ present ไปยังจออื่น และเฟรมที่ได้รับก็ผ่านการ compose มาแล้ว จึงไม่มีอะไรได้เพิ่ม
แลกกับการต้องดูแลคอมโพเนนต์ที่ต้องเซ็นดิจิทัล ผลพลอยได้คือ **แก้ shader ได้โดยไม่ต้อง
เซ็นไดรเวอร์ใหม่**

รายละเอียด: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) ·
อัลกอริทึมและตัวเลข: [`docs/ALGORITHMS.md`](docs/ALGORITHMS.md)

## เริ่มใช้งาน

**ต้องมี:** Windows 10 build 16299 ขึ้นไป, GPU ที่รองรับ D3D11,
[Visual Studio + WDK](https://learn.microsoft.com/windows-hardware/drivers/download-the-wdk)
สำหรับไดรเวอร์ และ CMake สำหรับคอมโพสิเตอร์

ขั้นตอนติดตั้งเต็ม รวมเรื่องการเซ็นไดรเวอร์: [`docs/BUILD-WINDOWS.md`](docs/BUILD-WINDOWS.md)

```powershell
# คอมโพสิเตอร์
cmake -B build -S . -A x64
cmake --build build --config Release

# ดูว่ามีจออะไรบ้าง
.\build\host\visual4k-host\Release\visual4k-host.exe --list-displays

# รัน (auto-detect จอเสมือน)
.\build\host\visual4k-host\Release\visual4k-host.exe

# ปรับจูน
visual4k-host.exe --kernel lanczos2 --sharpness 0.0    # เดสก์ท็อป/ตัวหนังสือ
visual4k-host.exe --kernel lanczos2 --sharpness 0.25   # เกม (ค่า default)
visual4k-host.exe --kernel lanczos3 --sharpness 0.5 --denoise --linear   # วิดีโอ
```

กด `Esc` เพื่อออก

## พัฒนาต่อ

แกนอัลกอริทึมทั้งหมดมี reference implementation บน CPU ที่เป็น **ตัวตัดสินความถูกต้อง**
— ถ้า shader กับ Python ไม่ตรงกัน แปลว่า shader ผิด และมี harness ที่พิสูจน์ว่า tap table
ฝั่ง C++ ตรงกับ Python ที่ความแม่นยำ float32 (ค่าต่างสูงสุด 3e-8)

```bash
pip install numpy pytest
python3 -m pytest reference/tests -q     # 69 tests
python3 reference/bench_supersample.py   # รันการวัดผลข้างบนใหม่

# self-test ที่ไม่ต้องใช้ Windows
cmake -B build -S . && cmake --build build && ctest --test-dir build
```

| ที่อยู่ | สิ่งที่อยู่ข้างใน |
|---|---|
| `reference/` | โมเดล CPU ที่เป็นบรรทัดฐานของไปป์ไลน์ + เมตริกคุณภาพ |
| `shaders/` | HLSL compute shaders (resolve, RCAS) |
| `host/visual4k-host/` | คอมโพสิเตอร์ D3D11 |
| `driver/Visual4kDisplay/` | ไดรเวอร์จอเสมือน IddCx |
| `tools/` | self-test ข้ามแพลตฟอร์ม (tap table parity, EDID) |

## สถานะ

| ส่วน | สถานะ |
|---|---|
| แกนการ resample + เมตริก | ทดสอบแล้ว 69 tests ผ่าน |
| C++/Python tap table parity | ตรวจสอบแล้ว (delta 3e-8) |
| EDID ของจอเสมือน | ตรวจสอบแล้ว (checksum + timing 60.00 Hz) |
| HLSL shaders | เขียนแล้ว **ยังไม่ได้คอมไพล์** — ต้องมี Windows + D3D |
| คอมโพสิเตอร์ D3D11 | เขียนแล้ว **ยังไม่ได้คอมไพล์** — ต้องมี Windows SDK |
| ไดรเวอร์ IddCx | เขียนแล้ว **ยังไม่ได้คอมไพล์** — ต้องมี WDK |

ส่วนที่ยังไม่ได้คอมไพล์เขียนขึ้นในสภาพแวดล้อม Linux ที่ไม่มี Windows SDK/WDK
คาดว่าจะต้องแก้ compile error รอบแรกบ้าง ตรรกะเชิงตัวเลขที่คุณภาพของภาพขึ้นอยู่กับมัน
ถูกแยกออกมาไว้ในส่วนที่ทดสอบได้แล้วทั้งหมด
